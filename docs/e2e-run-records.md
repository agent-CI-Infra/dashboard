# E2E 执行记录

## 功能

E2E 页的“E2E 执行记录”直接按类别（现有分片）列出用例，每个用例展示保留期内各次执行的状态时间轴。类别、用例是列表主体，单次运行只出现在对应历史点的提示中。页面自动读取已经发布的 JSON，不需要先点开某次运行，也不新增采集或下载产物。

计数和状态沿用[测试报告契约](test-reports.md)的 Playwright outcome 规则；E2E 页其他用例计数卡片和设置弹窗保持不变；Real E2E 质量评分使用同样的“类别 → 用例 → 状态轴”排版，另在用例下画分数曲线，见[页面与交互](dashboard-pages.md)。

## 使用方式

- **类别与用例**：打开E2E 页就能看到分片及其用例，标题在桌面和 390px 窄屏完整换行。点击类别标题可收起或展开用例，默认展开；标题按钮也支持键盘 Enter／空格操作。可按最新一次结果筛选，或搜索分片、用例标题和文件名。
- **执行时间轴**：按创建时间由早到晚，从左到右排列；空间不足时从下一行继续。保留期内的所有历史点一次展示，时间轴没有滚动条，也不撑宽页面。颜色和符号分别表示失败、重试通过、跳过、通过，区块上方提供文字图例。鼠标悬停或键盘 Tab 聚焦到点时，显示该次状态、浏览器时区的完整日期、耗时、运行名称／ID 和测试项目；点本身不铺开这些详情。
- **HTML 记录**：有已托管附件的历史点可在新标签页直接打开这一次的 `e2e/<artifact_id>/<分片>/data/<hash>.html`。无附件或未托管的点不提供链接，不退回 `index.html`。
- **页面内容**：每个用例只保留标题、文件、执行次数、最新状态和状态轴；不再显示步骤、错误摘要、运行详情，也不新增用例弹窗。需要旅程内容时，打开对应历史点的 HTML 附件。
- **数据范围**：只汇总当前分支线、已发布索引保留的记录；未下载或没有步骤的记录跳过。个别 JSON 读取失败不影响其他用例，刷新视图后可重试。历史保留期跟随源产物，过期记录移出索引后不再出现在时间轴中。

## 主要实现

### 浏览器按用例汇总

`static/app.js` 从 `data/e2e/index.json` 选取当前分支线的记录，自动读取已有 `data/e2e/<artifact_id>.json`，每批最多并行四份请求。读取结果按产物 ID、记录版本和 bundle 缓存在当前页面内存中；重复刷新复用未变化的 JSON，记录版本或 bundle 变化时重新读取。

用例身份严格使用“分片 + 文件 + 标题”，不使用行号、状态或运行 ID。文件内的行号变化不会拆分用例，不同分片或不同文件的同名用例也不会混在一起。每个历史点保留对应记录与用例数据，以索引 `created_at` 排序；没有耗时的数据展示 `—`，不会当作 0。结果筛选只根据最新一次执行判断是否显示该用例，保留其完整时间轴。

类别收起状态按分片名保存在当前页面内存中。异步 JSON 加载、手动刷新和定时刷新重绘均沿用该状态；搜索内容非空或启用最新结果筛选时，重绘会自动展开仍有匹配用例的类别，不覆盖手动选择，清空筛选后恢复原折叠状态。该状态不写入站点数据或浏览器持久存储，重新加载页面后默认展开。状态轴使用可换行的紧凑点阵，鼠标和键盘复用同一提示信息。

HTML 路径复用步骤 JSON 已有的 `html` 字段，并继续验证安全相对路径和当前部署的分片托管状态。fork、超限或 bundle 未挂载的历史点不会生成站内链接。这一视图没有修改记录版本（仍为 3）、下载额度、独立预算、失败保留逻辑或产物保留期，也不会触发 GitHub 采集。

### 采集：每次有界替换

`publish.py --incremental` 生成快照后调用 `gsb/e2e_records.py` 的 `refresh()`：

1. 只请求一次 `GET /repos/{源仓}/actions/artifacts?name=e2e-results&per_page=100`。只读第一页，不带页码，也不保存游标，因此不会回扫更早的产物历史。
2. 只保留出现在本次快照中的运行，包括各分支线 CI 分层历史里的运行和最近 run。去掉 `expired` 为真或 `expires_at` 已过的产物，再按创建时间取最新 20 份。
3. 同一产物、同一记录版本的已有记录直接沿用。当前记录版本为 3，旧版本中已就绪的记录会按最新优先重新下载，以补齐用例的附件 HTML 路径；版本 2 的旅程截图修复继续保留。每次最多处理 2 份待下载产物，版本升级不回扫历史页。
4. 升级尚未轮到、下载失败、解析失败或额度用尽时，已有 `ready` 记录继续保留原版本、步骤、报告与 bundle；只有新记录成功构建后才替换。旧版本不会被提前标记为已升级，后续采集仍会重试。没有旧可用记录的产物才显示等待或不可读取。列表请求失败时不下载，过期或离开窗口的记录仍按正常规则移除；单条失败不阻止整次采集。
5. 每次都输出完整的记录集合：索引 `site/data/e2e/index.json`，以及每份产物的步骤文件 `site/data/e2e/<artifact_id>.json`。离开集合的记录，其步骤文件在同一个提交里删除。issue、PR、CI 的增量同步不受影响，`.sync/` 不保存任何执行记录状态。

`publish.e2e_run_records()` 通过 `Budget.separate_phase()` 建立执行记录专用预算：最多 3 次封装调用（一次产物列表、两次下载），独立 120 秒时间预算。下载直接使用同一个底层 GitHub 客户端，不再经过主采集已经耗尽的 160 MiB 下载计数；主采集的额度不变。执行记录单份 ZIP 最多 80 MiB，两份新增下载合计最多 160 MiB，不能无限追加。`GSB_ARTIFACT_MAX_MB` 可以降低这个单份上限，但不能提高它。

同次主采集已经下载的 ZIP 通过共享内存缓存复用，缓存命中也会检查单份上限。汇总中的 `attempted` 表示尝试数，`downloaded` 表示成功取得 ZIP 字节的数量（包含缓存复用），`retained` 表示继续沿用旧版本 ready 记录的数量；两次失败不会再报告 downloaded 为 2。保留旧报告时预留其站点容量，替换成功后释放旧容量，避免新旧报告被重复计入 256 MiB 上限。

### 采集保留的用例数据

每个分片取带 `suites` 的 Playwright JSON 报告（`results.json`／`report.json`）。每个测试使用最后一次尝试的 `results[].steps`，保留嵌套层级，最多 8 层。每份产物最多保存 3,000 个步骤和 500 个用例的明细，超出部分仍计入计数。这些步骤与错误字段继续保留在已发布 JSON 中，但本页不渲染步骤、错误摘要或运行详情。

用例的可选 `html` 字段是分片内的安全相对路径，例如 `data/<hash>.html`。采集读取最后一次尝试的 `attachments`，把附件原始字节与同一分片 `playwright-report/data/*.html` 匹配；使用的字节是在截图链接改写之前的内容。Playwright JSON 中的 CI 绝对附件路径仅用于定位 ZIP 内的 `test-results/`、`journey-reports/` 或 `playwright-report/` 成员，不访问本地文件，不写入步骤 JSON；内联 base64 HTML 附件也按字节匹配。不会借用上一次尝试或其他分片的报告。只在整个分片通过托管检查后写入匹配路径，找不到匹配就省略该字段。

带 `error` 的步骤判为失败。用例的错误摘要取最后一次失败尝试的第一条错误，去掉终端颜色和 `at` 栈帧，最多保留 16 行、1,200 个字符。

### HTML：随 Actions 产物保存，不进 Git

HTML 报告及截图提交进 Git 会让历史永久增长，所以它们只在 Actions 和 Pages 之间传递：

1. 采集把新下载、且允许托管的分片报告写到 `.tmp/e2e-html/<artifact_id>/<分片>/`，包括 `playwright-report/` 下的 `index.html`、`data/` 等资源，以及该报告引用的 `journey-reports/<规格>/<用例>/` 目录。
2. `collect.yml` 用 `run_records.py retention` 从这些报告中最晚的 `expires_at` 算出保留天数（1–90 天），再把目录上传为本次运行的 `e2e-html` 产物。索引的 `bundle` 字段记录报告所在的采集 run。
3. `pages.yml` 上传站点前运行 `run_records.py attach site`。它用本 job 的 `GITHUB_TOKEN`（`actions: read`）读取索引中未过期记录所在的 `e2e-html` 产物，只接受本仓 main 分支上的 `collect.yml` 运行。采集先提交、后上传，因此 Pages 会等待该运行最多 5 分钟。
4. 取不到的报告在部署出的索引里改为 GitHub 链接。已过期的记录连同其步骤文件从部署内容中移除。这一步任何失败都不会阻止 Pages 部署。

采集打包与 Pages 挂载共用相同的相对路径校验，按原名保留中文、空格、括号等截图与附件，使 HTML 中的相对引用保持有效。每段长度为 1–128 个字符，不能是 `.` 或 `..`，不能含路径分隔符、控制字符或 Unicode 代理码位；绝对路径和空路径段也会被丢弃。不把反斜杠改成斜杠，也不对文件名进行归一化后再放行。

Playwright 的 HTML 附件可能只有 `data/<hash>.html`，截图仍留在原始旅程目录。采集以 HTML 原始字节内容匹配同一分片 `journey-reports/.../report.html`，只带上匹配目录的报告与附件；未被引用的旅程目录及 `test-results/` 不发布。`data/<hash>.html` 地址保持不变，其中实际 HTML 标签的相对 `src`／`href` 改写为 `../journey-reports/<规格>/<用例>/...`（目录部分做 URL 编码），原旅程目录的 `report.html` 保持原文。绝对地址、带协议的链接、仅锚点或查询参数的链接保持不变，脚本文本也不改写。各用例保留独立目录，同名步骤截图不会覆盖。

单片大小按 Playwright 报告、所选旅程目录及改写后的 HTML 合计计算，超过 40 MiB 仅放弃该片的 HTML 托管，仍保留用例数据及 GitHub 产物地址，不中断采集；状态轴中的未托管历史点不生成链接。

## 边界与阈值

| 项 | 阈值 | 超出后 |
| --- | --- | --- |
| 看板上的记录 | 最新 20 份 | 更早的运行只在 GitHub 查看 |
| 每次采集新下载 | 2 份 | 标为等待，后续采集补齐 |
| 单个产物下载 | 最多 80 MiB（`GSB_ARTIFACT_MAX_MB` 可降低） | 保留旧 ready 记录；没有旧记录时标为超过上限 |
| 执行记录专用新增下载 | 最多 2 份、合计最多 160 MiB | 后续采集重试，保留已有可用记录 |
| 单个分片的 Playwright 报告及引用的旅程目录 | 40 MiB | 保留用例数据，历史点不生成 HTML 链接 |
| 看板上 HTML 总量 | 256 MiB | 同上 |

- 保存期限以 GitHub 返回的 `expires_at` 和 `expired` 为准，不写死 14 天。过期后的下一次成功采集删除步骤文件；每次 Pages 部署也会按 `expires_at` 排除 HTML。看板自己的 `e2e-html` 产物在其中最后一个源产物过期后约一天内被 GitHub 清除。
- 来自 fork 的运行（产物的 `head_repository_id` 与源仓不同）保留用例状态，其 HTML 不在看板域名下托管，历史点不是链接。
- trace、截图、视频不另外长期归档。`playwright-report/data/` 及被引用旅程目录里的附件随报告保留；`test-results/` 等其余内容请下载 GitHub 产物。
- 页面只把校验通过的用例 `data/.../*.html`（通常为 `data/<hash>.html`）相对路径与该产物、分片组合成站内链接。每段名称按原名 URL 编码，并检查本次部署索引仍标记该分片已托管；索引的 `reports[].html` 保留作托管标记，不再成为导航入口。旧版本待升级记录仍显示已有状态，成功刷新后才出现单条 HTML 链接。

## 验证

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest tests.test_e2e_records tests.test_publish -v
node .e2e/node_modules/playwright/cli.js test --config test/playwright.config.cjs -g "E2E run records"
```

`tests/test_e2e_records.py` 覆盖以下内容：
- 嵌套步骤、失败摘要和重试前失败，计数与原解析器一致；
- 最后一次尝试的附件字节映射、无附件不生成链接、危险路径拒绝、内联 HTML 和未托管分片不生成站内路径；
- 单次列表请求、无游标、下载上限；
- 旧版本已就绪记录按最新优先重下，仍遵守每次 2 份的限制；
- 主采集字节、请求及时间额度用尽后，独立阶段仍能列出并下载两份执行记录；缓存复用与 80 MiB 单份硬上限；
- BudgetExhausted／GitHub 下载失败及暂未轮到时，原步骤、报告、bundle 保留且可由 Pages 挂载，后续成功再替换；站点容量不重复计入旧报告；
- 中文、空格、括号截图从源 zip 到采集 bundle 再到 Pages 保留原名，拒绝越界、控制字符及超长路径；
- 按真实产物布局匹配 hash HTML 与旅程报告，挂载后相对链接能读取对应 PNG 字节，同名截图隔离、外部链接和脚本不改写；
- 25 MiB 以上的完整旅程分片可托管，41 MiB 分片只降级 HTML，步骤与采集结果仍可用；
- 过期记录的删除，以及 fork、超预算、GitHub 失败时的降级；
- Pages 只挂载未过期报告、会等待上传、拒绝非采集运行的产物；
- 保留天数计算。

`tests/test_publish.py` 验证只有执行记录文件可以在提交中删除。

浏览器夹具 `test/prepare-site.py` 用真实的 `refresh()` 和 `attach()` 生成跨运行、跨分支线的记录，包含过期、fork、超限及同名用例。旅程验证打开页面就能看到“分片 → 用例 → 时间轴”，同一用例的四次执行按时间列出失败、重试通过、跳过和通过，并通过悬停／聚焦提示显示各自耗时；行号变化不拆分，不同文件或分片的同名用例保持独立。

类别默认展开，可通过鼠标或键盘折叠；旅程验证手动与 60 秒定时刷新保留折叠状态，搜索／筛选自动展开匹配类别，清空后恢复手动选择，并断言页面不再存在步骤与错误摘要。

桌面和 390px 窄屏用 20 份记录验证完整状态轴、长标题换行、全部点位于轴内、轴没有滚动条且页面无横向溢出；悬停及键盘聚焦均能读到状态、完整日期、耗时和运行信息。有附件历史点直达 hash HTML，三张中文截图可读取；无附件、非法路径、fork 及挂载失败不出现站内链接。另覆盖个别步骤 JSON 404、分支线隔离、刷新重试、缓存复用和记录版本变化。设置弹窗和 Real E2E 内联曲线由各自的旅程覆盖。
