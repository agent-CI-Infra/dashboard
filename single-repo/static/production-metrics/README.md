# DigitalMate production metrics view

Assets are adapted from DigitalMate `dashboard/e2e-performance` (commit `c07077d`). The view reads `data/production-model-history.json`, separately from nightly E2E data. `.github/workflows/collect-production-model-metrics.yml` publishes a 35-calendar-day aggregate daily to the imported `digitalmate` branch and triggers Pages deployment. Configure the `PRODUCTION_GATEWAY_KEY` Actions secret in the dashboard repository. The runner must be able to reach the gateway. Collection uses up to three concurrent daily windows and logs each completed window. A failed collection leaves the previous aggregate intact.

Only daily model aggregates are published; raw logs and request IDs are never written. The gateway rows are requests, not user questions. All traffic on the configured gateway is included; production versus test traffic is not independently classified. Unknown-status records make the selected model/day failure rate unavailable. Missing token values stay unavailable, not zero. The current day is partial and date windows use the newest available date across models. TTFT and TPOT are timestamp-based estimates for successful calls with ordered timestamps, including calls whose streaming status is unknown; explicitly non-streaming calls are excluded. Unknown streaming status means these estimates may not measure actual first-token latency. TTFT is completionStartTime minus startTime; TPOT is (endTime minus completionStartTime) divided by (completion_tokens minus one). P95 uses successful gateway durations and requires 20 samples; an aggregate interval is unavailable when any contributing source with samples lacks a P95. Other boards do not show this tab.

The production metrics tab also displays a separate Nightly E2E client breakdown from `data/e2e-performance/history.json`. It is not attributed to the selected production model. Stage bars are averaged only from queries with all six ordered stage pairs; missing instrumentation is not inferred from gateway data. The graph retains one point per case/day/explicit region and network, while the legacy E2E history continues to keep one point per case/day. Region/network labels are supplied by the E2E runner, not automatically detected. The existing DigitalMate artifact collector and its `DIGITALMATE_TOKEN` are required; old histories have no breakdown until new artifacts are merged. Any `demo` history is visibly marked and local preview fixtures must not be published as production telemetry.
The optional daily details table is collapsed initially. It reports stage sample counts and, when a matched benchmark model aggregate supplies it, cloud TTFT with model and sample count. Existing E2E artifacts may not carry this aggregate, in which case TTFT remains unavailable.
